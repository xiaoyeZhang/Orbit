- **编译回归修复(1855a43)**:d4eedfc 的浅色模式中,Palette 的 `separator` 与 `adaptive` 辅助用了 `UIColor { t in ... }` 尾随闭包初始化器——该 init **仅 iOS 17+ 可用**,而 Orbit 部署目标 iOS 16,导致编译器类型推断卡死报 "The compiler is unable to type-check this expression in reasonable time"。已改为 `UIColor(dynamicProvider: { t in ... })`(iOS 13+,向后兼容),自适应逻辑不变。这是用户贴出 `UIColor(srgbRed:...)` 辅助方法后定位到的根因。
  · 🚫 教训:**本工程最低部署 iOS 16,禁止用 iOS 17+ 专属 API**。自适应 UIColor 必须用 `UIColor(dynamicProvider:)`,不要用 `UIColor { }` 尾随闭包版。引入任何 `init`/方法前先确认可用性区间。
