## 本环境构建限制（重要，下次直接照做）
- `xcodebuild` / `swift package resolve` 的 SPM 解析阶段会调 `/usr/bin/sandbox-exec`，被系统拒绝：`sandbox-exec: sandbox_apply: Operation not permitted`，导致**无法重新解析/编译**（即使 `dangerouslyDisableSandbox` 也无效，因为是绝对路径调用，PATH 包装拦截不到，SIP 保护无法替换）。
- 表现：`.xcodeproj` 本地包（OrbitCore/OrbitUI/OrbitServices 互相 path 引用，无远程依赖）也照样解析失败。
- 现状：模拟器 iPhone 17 (id 5A7FF6D1-1023-44E7-9E41-E7DE10EF34C6) 已装旧版 app（含前 9 类修复，但天气按钮仍是「条件显示」旧逻辑）。
- **在 shell 里直接 Build & Run 不可行时**：在 Xcode GUI 里 Build & Run 正常（GUI 不受此沙箱限制）。
- 验证 UI 的替代手段：`xcrun simctl` 设模拟定位（`location run "Apple"` 等预设）、`simctl launch/terminate`、`simctl io <dev> screenshot /tmp/x.png` 截图后用 Read 查看。地图页天气按钮依赖真实坐标（否则 userCoordinate=nil、天气拉不到、按钮不显示），故演示前务必先设模拟定位。

## 修复 Instance member 'font' cannot be used on type 'View'（commit b18f765）
- 报错根因：视图修饰符（.font 等）接在「被推断为 View 存在类型」的 if/else/switch 整块上（分支类型不同时触发）。
- 定位：逐行核对本会话改过的 8 个视图文件 + RootView，且 8659abf 构建成功 → 已提交代码无此错；唯一脆弱写法在 MapHomeView 天气按钮（.font 接在 if/else 整块后）。
- 修复：天气按钮改用三元表达式 `Label(temperature!=nil ? ... : "天气", systemImage:)`，修饰符明确作用于 Label，并让按钮始终显示。
- 经验：若用户在 Xcode 报此错但已提交代码能编译，多半是用户本地未保存改动；需其提供报错的文件:行号精确定位。
- 触发词示例："run it and let me see"、"截图地图页"、"build and install on the simulator"。
